# Documentation Agent Metadata & Workflow Skill

## Overview

This skill defines how the Slack Documentation Agent paths through the document transformation workflow and structures information for Merge Requests. It ensures consistent metadata collection, processing stages, and MR generation with full context and audit trails.

## Agent Workflow Path

The agent follows a deterministic path from Slack intake through documentation generation to MR creation:

```
Slack Input
    ↓
[Stage 1] Intake → Collect source metadata
    ↓
[Stage 2] Parse → Extract and chunk content
    ↓
[Stage 3] Transform → Generate markdown with Copilot SDK + Skills
    ↓
[Stage 4] Output → Save with metadata
    ↓
[Stage 5] MR Creation → Push to VCS and open MR with GitLab/GitHub SDK
    ↓
Slack Notification → Post MR link to thread
```

## Stage 1: Intake (Slack Channel)

**Purpose**: Capture incoming documentation artifacts with complete source context

**Metadata Collected**:
- `source_file`: Original filename (e.g., `API-Guide-v2.pdf`)
- `source_channel`: Slack channel ID
- `source_thread_ts`: Thread timestamp for status updates
- `upload_timestamp`: ISO 8601 timestamp of upload
- `file_size_bytes`: File size for logging and validation
- `file_type`: MIME type validation
- `uploader_user_id`: Slack user ID for credit/attribution
- `file_url_private`: Slack file download URL

**Validation Checks**:
- ✓ File type must be PDF or DOCX
- ✓ File size must be < 50MB
- ✓ Channel must be accessible
- ✓ User must have upload permission

**Output to User**: 
→ "📄 Processing [filename]... (Step 1/5)"

## Stage 2: Parse & Structure

**Purpose**: Extract text content and organize into semantic chunks for Claude

**Metadata Collected**:
- `parse_status`: 'success' | 'failed'
- `parse_duration_ms`: Processing time
- `total_chunks`: Number of semantic divisions
- `total_tokens`: Rough token count for Claude input
- `extracted_sections`: List of identified document sections
- `detected_language`: Language of source content
- `extraction_warnings`: Any issues encountered (images excluded, tables simplified, etc.)

**Processing Path**:
1. Download file from Slack
2. Run Python parser (PyPDF2 or python-docx)
3. Extract raw text
4. Chunk by semantic boundaries (paragraphs + headings)
5. Store chunks as JSON with metadata

**Output to User**:
→ "📊 Parsed [X] chunks, [Y] tokens... (Step 2/5)"

## Stage 3: Transform (Copilot SDK + Skills)

**Purpose**: Use Claude with available skills to generate professional markdown

**Metadata Collected**:
- `generation_status`: 'streaming' | 'complete' | 'failed'
- `generation_duration_ms`: Total time for Claude generation
- `model_used`: Which model (claude-opus, gpt-4.1, etc.)
- `skills_applied`: List of skills Claude used (markdown-conversion, documentation-structure, etc.)
- `prompt_tokens`: Tokens sent to Claude
- `completion_tokens`: Tokens generated by Claude
- `output_sections`: Final section list (Overview, Features, Getting Started, etc.)
- `quality_score`: Validation pass/fail

**Processing Path**:
1. Build prompt with document chunks and project context
2. Reference available skills for markdown best practices
3. Stream generation response through Copilot SDK
4. Update Slack thread with progress chunks
5. Validate generated markdown structure
6. Collect output metrics

**Output to User** (Real-time):
→ "✨ Generating with Claude... [50%] [100%]"
→ "✅ Generation complete (Step 3/5)"

## Stage 4: Output & Storage

**Purpose**: Save generated documentation with complete metadata trail

**Metadata Collected**:
- `output_filename`: Generated filename (e.g., `api-guide-v2.md`)
- `output_path`: Full path in `processed_docs/`
- `output_size_bytes`: Size of generated markdown
- `word_count`: Total words in generated doc
- `section_count`: Number of sections created
- `code_block_count`: Number of code examples
- `save_timestamp`: When persisted to disk

**Storage Structure**:
```
processed_docs/
  ├── api-guide-v2.md                    # Generated markdown
  ├── api-guide-v2.meta.json             # Complete metadata
  └── api-guide-v2.log                   # Processing details
```

**Output to User**:
→ "💾 Saved markdown (Step 4/5)"

## Stage 5: MR Creation (GitLab/GitHub SDK)

**Purpose**: Create VCS branch and open Merge Request with processed documentation

**Branch Naming Convention**:
```
docs/auto-[source-basename]-[YYYYMMDD-HHMMSS]
```

Examples:
- `docs/auto-api-guide-20260306-032415`
- `docs/auto-architecture-doc-20260306-032500`

**Commit Message Format**:
```
docs: Auto-generated documentation from [source-filename]

Source: Slack [channel] / [uploader]
File: [source-filename] ([size] bytes)

Processing Summary:
  Parse: [duration]ms → [chunks] chunks, [tokens] tokens
  Generation: [duration]ms → Claude [model]
  Sections: [list]

Skills applied: markdown-conversion, documentation-structure
Quality: PASSED
```

**MR Title Format**:
```
docs: Add [project-name] documentation from [source-file]
```

**MR Description** (includes full processing metadata):
```
## 📋 Generated Documentation

**Source**: [filename] (uploaded by @user to #channel)
**Processing Time**: [total duration]

## 🔄 Transformation Pipeline

| Stage | Duration | Result |
|-------|----------|--------|
| Parse | [X]ms | [chunks] chunks, [tokens] tokens |
| Generate | [X]ms | Claude [model] |
| Output | [X]ms | [word count] words, [sections] sections |

## 📊 Document Details

- **Sections**: [list of generated sections]
- **Code Examples**: [count]
- **Quality Check**: ✅ PASSED

## 🎯 Next Steps

- Review the generated markdown in this MR
- Request changes if needed from reviewers
- Approved MRs will be merged to main documentation

Generated by Slack Documentation Agent
```

**MR Labels** (auto-applied):
- `auto-generated` - Always applied
- `documentation` - Always applied  
- `from-slack-bot` - Always applied
- `needs-review` - Always applied
- Category labels (if detected): `api-docs`, `architecture`, `guide`, `tutorial`

**Output to User**:
→ "🔗 MR Created: [link] (Step 5/5)"
→ "✅ Documentation generation complete!"

## Processing Path Decision Tree

```
Document received (Slack file_shared event)
  ├─ Valid type (PDF/DOCX)?
  │  ├─ NO  → Send error to Slack, halt
  │  └─ YES → Continue
  ├─ Parse successful?
  │  ├─ NO  → Send error to Slack with details, halt
  │  └─ YES → Continue
  ├─ Has extractable content?
  │  ├─ NO  → Send warning to Slack, halt
  │  └─ YES → Continue
  ├─ Generate markdown (Copilot SDK)
  │  └─ Stream updates to Slack
  ├─ Validation passed?
  │  ├─ NO  → Log warnings, continue
  │  └─ YES → Continue
  ├─ Save locally with metadata
  └─ Create MR (GitLab/GitHub SDK)
     ├─ Create branch
     ├─ Commit markdown + metadata
     ├─ Open MR with formatted description
     └─ Post MR link to Slack thread
```

## Best Practices

1. **Always collect metadata** at each stage for complete audit trails
2. **Include processing context in MR descriptions** (source, duration, model, skills applied)
3. **Preserve metadata JSON** alongside outputs for future reference and re-use
4. **Real-time Slack feedback** at each major processing stage
5. **Predictable naming** for branches, commits, and output files (enables automation)
6. **Detailed error messages** sufficient for debugging and manual recovery
7. **Immutable records** - never delete metadata JSON or processing logs
